Platform foundation

Release trust, made inspectable.

FirmwareTrust begins with a focused host-side toolchain: create a signing identity, describe an artifact in a signed manifest, then verify it against a separately supplied trust anchor.

⌘

Cryptographic signing

Ed25519 signatures bind release metadata to a signing key, enabling independent authenticity checks.

#

Artifact integrity

SHA-256 digests and byte-size metadata let the verifier detect changes to the firmware artifact.

{ }

Deterministic manifests

Canonical JSON serialization creates a stable payload for signature generation and verification.

✓

Independent verification

The verifier receives a trusted public key separately; a key named by the manifest is not trusted automatically.

⌁

Command-line workflow

Key generation, signing and verification are exposed through a Python CLI for repeatable engineering workflows.

Security boundaries

Trust starts with honest boundaries.

A valid signature proves that signed data matches a particular private key and artifact digest. It does not prove the firmware is benign, the signer is authorized, or the device will enforce the policy.

Current maturity: M0 prototype.

FirmwareTrust is not currently a secure-boot implementation, OTA updater, device provisioning system, anti-rollback mechanism or production key-management service. Production use requires independent trust-anchor provisioning, hardened key custody, rotation and revocation controls, operational procedures, security review and target-specific validation.
