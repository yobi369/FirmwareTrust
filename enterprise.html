Signing-key lifecycle

Register public verification keys, rotate active keys and revoke compromised keys.

PRIVATE KEYS STAY LOCAL

Select a project to load its signing keys.

Rotation atomically retires the old key and registers its successor. Revocation is irreversible. FirmwareTrust stores public verification material only; never paste or upload a private key.

Release registry

Select a project to register and review release metadata.

Attach the signed manifest to verify its Ed25519 signature against an active registered key and bind it to this organization/project. Firmware binaries are never uploaded. Without a manifest, only unsigned draft metadata is recorded.

Release policies & evaluation

Define versioned release controls and evaluate a selected draft against current evidence.

Supported rules: require_signed_manifest, require_sbom, require_complete_sbom_scan, block_on_critical, max_high_findings and min_approvals. Policy creation is restricted to organization owners/admins. Evaluation is read-only and does not publish a release.

SBOM & vulnerability intelligence

Inventory software components and identify known vulnerabilities in the selected project.

Supports CycloneDX JSON and SPDX JSON. The original SBOM is stored with a SHA-256 digest; versioned package URLs are checked against OSV.dev. Firmware binaries are not uploaded.

Recent vulnerability findings

Current implementation boundary: authenticated organization creation, membership-scoped workspace access, project records and draft release metadata are being brought online first. Release review requests, independent approval decisions and policy-gated approval status are implemented. Publication is gated by server-created cryptographic verification attestations and fresh policy checks. Team invitations, scoped API tokens, signed webhooks and enterprise reporting remain gated until their runtime services and security tests are complete.
